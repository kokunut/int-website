## ADR-006 "오늘" 의존 UI는 클라이언트에서 재확인
- 2026-11-01 · 채택

- 이유: ISR은 오래 방치되면 첫 요청에 이전 페이지를 내보내므로(stale-while-revalidate) 날짜가 하루 이상 지날 수 있음.

## ADR-007 편집 가능한 문구는 페이지 코드가 아닌 콘텐츠로
- 2026-11-01 · 채택
- 결정: 문단 단위 문구(인사말, 신청 절차, 유의사항 등)는 `src/content/pages.ts` → 데이터 레이어 getter로 제공. 페이지에는 짧은 UI 라벨만 둔다.
- 이유: 다음 집행부가 페이지 코드를 몰라도 수정 가능, 이후 노션 연동 대상으로 옮기기 쉬움.

## ADR-008 콘텐츠 연동: 서비스 계정 없이 게시 CSV·iCal + 노션 fetch
- 2026-11-01 · 채택
- 결정: 구글은 서비스 계정/API 없이 시트 `요약` 탭의 "웹에 게시" CSV와 캘린더 iCal URL만 읽는다. 노션은 SDK 없이 `fetch`로 호출하고 `Notion-Version: 2022-06-28`을 고정한다. 소스별로 환경변수가 없거나 실패하면 목 데이터로 폴백한다. 즉시 갱신은 `POST /api/revalidate`(비밀 헤더).
- 이유: 비밀키·권한 설정이 줄어 다음 집행부 인수인계가 쉽고, 의존성이 없으며, 노출 범위가 게시한 집계 탭으로 제한됨. 한계: iCal 반복 일정 미지원.

## ADR-009 웹폰트 자체 호스팅 (Pretendard 가변 dynamic-subset)
- 2026-11-01 · 채택
- 결정: CDN `<link>` 대신 `pretendard`(1.3.9) npm 패키지의 `pretendardvariable-dynamic-subset.css`를 `layout.tsx`에서 import해 번들에 포함한다. `font-family`는 `'Pretendard Variable', Pretendard, …`. 폰트 CSS는 `font-display: swap`.
- 이유: 외부 CSS가 렌더링을 약 950ms 차단했고 외부 도메인 의존이 생김. dynamic-subset은 화면에 쓰인 글자 조각만 받아 전송량이 작음.

## ADR-010 팝업 SSR + 첫 페인트 전 숨김
- 2026-11-01 · 채택
- 결정: 메인 팝업은 서버(`page.tsx`, `todayKST()` 기준)에서 후보를 골라 초기 HTML에 포함한다. "보지 않기"는 팝업 앞의 인라인 스크립트(`popupHideScript`)가 `localStorage`와 KST 오늘 날짜를 비교해 `<html data-popup-hidden>`을 표시하고, CSS(`html[data-popup-hidden] .modal{display:none}`)가 첫 페인트 전에 숨긴다. 클라이언트 컴포넌트는 하이드레이션 후 기존 로직으로 재판정하며(ADR-006) 서버와 다르면 클라이언트가 우선한다. 초기 상태는 localStorage를 쓰지 않아 하이드레이션 경고가 없다. `requestIdleCallback` 지연은 제거. 하이드레이션 전에는 같은 스크립트가 "닫기"·배경 클릭·Esc를 위임 이벤트로 처리해 `data-popup-hidden`을 표시하고(체크박스 값은 localStorage에도 저장), 컴포넌트는 마운트 시 이 표시를 닫힌 상태로 이어받으며 모달에 `data-ready="true"`를 붙인다. E2E는 `[data-ready=true]`를 기다린다.
- 이유: 마운트 후에 그리면 팝업 본문이 LCP가 되어 늦어지고, 유휴 지연은 오히려 더 늦춤. 스크립트의 규칙은 `isSuppressed`와 같으며 단위 테스트로 고정.

## ADR-012 노션 이미지 안정 경로(프록시)
- 2026-11-02 · 채택
- 결정: 노션 업로드 파일은 `GET /api/notion-file/[pageId]/[field]/[index]`(307 리다이렉트, 5분 캐시)로 내보낸다. `field`는 허용 목록(`banner-image`, `banner-image-mobile`, 이후 확장), `index`는 0~19. 페이지의 `parent.database_id`가 해당 필드의 `NOTION_DB_*`이고 `공개`가 체크된 행이며 https 파일일 때만 응답하고, 그 외·토큰 없음·조회 실패는 이유 없이 404. 외부 링크(`external`)는 기존대로 원래 URL.
- 이유: 서명 URL은 약 1시간 뒤 만료되어 ISR 캐시가 길면 이미지가 깨진다. 내부 경로는 만료되지 않고, 공개 행·허용 필드만 열어 임의 페이지 파일 노출을 막는다. 남용 방지: 노션 호출 전에 해당 DB의 캐시된 목록 조회(`queryDatabase`, 배너 로더와 같은 요청·10분 캐시)에 pageId가 있는지 확인하고 없으면 노션 호출 없이 404, 목록 행에 서명 URL이 있으면 그대로 사용하며 `fetchPage`는 행은 있으나 URL이 없을 때만 보충한다(`resolveFileUrl`). 한계: 이미지 요청마다 서버 함수가 한 번 실행될 수 있다(5분 캐시로 완화).

## ADR-013 범용 팝업: 노션 "팝업" DB + 공모전 합치기
- 2026-11-02 · 채택
- 결정: 제휴·행사·공지 팝업은 노션 "팝업" DB(`NOTION_DB_POPUPS`, `DB_SPECS`에 포함 → `notion:setup`·`content:check` 자동 반영)에서 관리자가 직접 추가·수정·삭제한다. 속성: 제목·슬러그·분류(제휴/행사/공지/공모전)·기간(KST)·내용·이미지(`popup-image` 안정 경로, ADR-012)·링크(`safeHref`)·버튼문구·순서·공개. 메인(`/`)에서만, 오늘(KST)이 기간 안인 팝업과 기존 `팝업` 체크 공모전(분류 "공모전"으로 변환, `buildPopups`)을 합쳐 순서대로 보여준다. 슬러그가 겹치면 팝업 DB 우선, 순서가 없으면(공모전 포함) 맨 뒤, 같으면 입력 순서. 환경변수가 없으면 `src/content/popups.ts` 목 데이터.
- 이유: 제휴·행사 공지를 코드 수정 없이 노션 행 추가만으로 올리고 `공개` 해제·삭제로 내리게 하려는 것(활용 방식 e). 공모전은 이미 `팝업` 체크 흐름이 있어 별도 입력 없이 같은 모달로 합친다. 한계: 팝업 행도 10분 ISR 캐시를 따른다(즉시 반영은 `/api/revalidate`).

## ADR-014 "보지 않기"는 열린 팝업 묶음 단위
- 2026-11-02 · 채택
- 결정: "오늘 하루/일주일간 보지 않기"는 현재 보이는 팝업 한 건이 아니라 **지금 열린 묶음 전체**에 적용한다. 저장 키는 기존 `int_popup_hide_<슬러그>` 그대로, 묶음의 모든 슬러그에 같은 만료일을 기록하되 이미 더 늦은 만료일이 있으면 줄이지 않는다(`mergeSuppress`). 새 팝업이 추가되면 그 슬러그만 키가 없어 다시 뜬다. 첫 페인트 전 스크립트(`popupHideScript(ids)`)는 묶음의 모든 슬러그가 숨김일 때만 `data-popup-hidden="<슬러그,…>"`를 표시하고, 일부만 숨김이면 하이드레이션 후 컴포넌트가 걸러낸다(ADR-006, 클라이언트 우선). 하이드레이션 전에는 이전/다음이 동작하지 않는다(닫기·Esc·배경 클릭만 처리).
- 이유: 여러 개를 넘겨 보는 한 모달에서 한 건에만 적용하면 사용자 기대("이 팝업창을 오늘 안 본다")와 다르다. 슬러그별 키를 유지해 새 팝업만 다시 띄울 수 있다. 한계: 일부만 숨김일 때 서버 HTML에는 숨긴 팝업도 포함되어 하이드레이션 직후 슬라이드 수가 줄 수 있다.

## ADR-015 카드뉴스 공지: 노션 공지 DB 속성 + 슬라이더
- 2026-11-02 · 채택
- 결정: 인스타그램 카드뉴스와 같은 내용을 공지로 게시하기 위해 공지 DB에 `카드뉴스`(files, 여러 장)·`인스타그램`(url) 속성과 `유형`의 **카드뉴스** 옵션을 추가한다(`DB_SPECS` → `notion:setup`·`content:check` 자동 반영). 업로드 파일은 `/api/notion-file/[pageId]/notice-images/[index]`(ADR-012, 인덱스 0~19)로, 외부 링크는 https만 원래 URL로 내보내며 순서를 유지한다. 인스타그램 링크는 `https://instagram.com`·`*.instagram.com`만 허용(`safeInstagramUrl`). 공지 상세는 본문 위에 슬라이더(`CardSlider`: scroll-snap 스와이프·이전/다음·점·"2 / 6"·←/→, 4:5 상자 + `contain`, 최대 560px, 첫 장 외 `loading="lazy"`)를 보여주고, 목록은 "카드뉴스" 배지·장수와 유형 탭을 제공한다(`isCardNews`: 유형이 카드뉴스이거나 이미지가 있는 공지). 첫 장은 `openGraph.images`(내부 경로는 절대 URL)로 쓴다. 버튼·키로 넘기는 중에는 목표 장을 ref로 들고 있어 애니메이션 중간 스크롤 위치가 현재 장을 덮어쓰지 않게 한다.
- 이유: 관리자가 노션에서 이미지만 올려 인스타그램과 같은 내용을 사이트에도 게시하게 하려는 것(활용 방식 c). 이미지 속 글은 검색·스크린리더가 읽지 못하므로 매뉴얼에서 본문 요약을 안내한다. 한계: 시드(`notion:setup --seed`)는 이미지 업로드가 필요해 카드뉴스 이미지를 넣지 않는다. 기존 DB는 속성·옵션을 수동 추가해야 한다.

## ADR-016 아카이브 메뉴: 취업 아카이브·병영 길라잡이, 노션 아카이브 DB, 공용 블록 렌더링
- 2026-11-02 · 채택
- 결정: 새 상위 메뉴 **아카이브**(자료실 옆)에 "취업 아카이브"(`/archive/career`)와 "병영 길라잡이"(`/archive/military`)를 둔다. 복지 메뉴의 "군입대 백서"(외부 링크)는 제거하고, 같은 사이트 링크 설정(`notionMilitary`)으로 병영 길라잡이 목록 상단의 링크 카드와 메인 바로가기(→ 병영 길라잡이)에 쓴다. 콘텐츠는 노션 "아카이브" DB(`NOTION_DB_ARCHIVE`, `DB_SPECS` 포함 → `notion:setup`·`content:check` 자동)에서 CRUD 하며 `분류`(취업/병영)로 나눈다. 슬러그는 분류 안에서 유일, 첨부(files)는 `archive-files` 안정 경로(ADR-012, 인덱스 0~19), 링크는 `safeHref`. 목록은 속성만 읽고 본문 블록은 상세에서만 요청한다(공지와 동일). 주제 탭은 정해 둔 주제 순서 → 새 주제 순이며 글이 없는 주제는 숨긴다.
- 블록 렌더링: 본문은 `ContentBlock`(문단·제목·목록·인용·콜아웃·구분선·이미지·체크리스트)으로 변환(`blocksToContent`, 연속 목록 항목은 하나로 묶음)해 공지·아카이브가 `NotionBlocks` 하나로 그린다. `heading_1`은 페이지 `h1`과 겹치지 않도록 `h2`로 그린다. 공지의 `body: string[]`는 캘린더 등 기존 사용처를 위해 그대로 두고 `blocks`를 더한다. 하위(중첩) 블록은 요청하지 않는다.
- 이유: 취업·병영 정보를 코드 수정 없이 올리고(활용 방식 d), 지금까지 텍스트 줄만 보이던 본문을 구조 그대로 보여 주기 위함. 한계: 업로드 이미지 블록은 서명 URL이 만료돼 아직 지원하지 않는다(외부 https 이미지만, 업로드 이미지는 후속). 글자 서식(굵게·링크)은 일반 글자로 표시된다. 기존 노션에는 아카이브 DB를 새로 만들어야 한다.

## ADR-011 방문 통계: Vercel Analytics·Speed Insights, 운영 배포에서만 렌더
- 2026-11-01 · 채택
- 결정: `@vercel/analytics`, `@vercel/speed-insights`를 쓰고 `layout.tsx`(서버 컴포넌트)에서 `isVercelProduction()`(`process.env.VERCEL_ENV === "production"`)일 때만 `<Analytics />`, `<SpeedInsights />`를 렌더한다. 커스텀 이벤트(`popup_detail`, `payback_apply`, `kakao_fab`)는 `src/lib/analytics.ts`의 `EVENTS`로 상수화하고, 클라이언트에서는 `next.config.ts`가 주입한 `NEXT_PUBLIC_ANALYTICS`가 `1`일 때만 전송한다(그 외 no-op). `track`은 이벤트 발생 시 동적 import 해 초기 JS에 포함하지 않는다.
- 이유: 무료이고 쿠키·개인 식별 정보가 없다. 미리보기(Preview) 배포도 `VERCEL=1`이라 집행부·리뷰어 트래픽이 섞이므로 운영(Production)만 집계한다. Vercel 밖(로컬 `next start`, CI)에서는 `/_vercel/insights/script.js`가 404여서 E2E 콘솔 에러 검사와 Lighthouse 권장사항이 실패한다. 한계: 커스텀 이벤트는 유료 플랜 기능일 수 있어 무료 플랜에서는 페이지뷰만 보일 수 있음(확인 필요).
