# 06. 콘텐츠 운영 매뉴얼

개발을 몰라도 사이트 내용을 고칠 수 있도록 정리한 문서입니다. 아래 표의 속성 이름은 코드(`src/lib/data/notion-schema.ts`)와 **글자 하나까지 같아야** 합니다. 이름을 바꾸면 사이트에 나타나지 않습니다.

## 1. 무엇을 어디서 고치나요?

| 내용 | 고치는 곳 | 반영 환경변수 |
| --- | --- | --- |
| 공지사항 | 노션 DB | `NOTION_DB_NOTICES` |
| 공모전 | 노션 DB | `NOTION_DB_CONTESTS` |
| 제휴 | 노션 DB | `NOTION_DB_PARTNERS` |
| 자주 묻는 질문 | 노션 DB | `NOTION_DB_FAQ` |
| 자료실(회칙·회의록·활동계획서·결산·서식) | 노션 DB 1개 (`분류`로 구분) | `NOTION_DB_DOCS` |
| 취업 아카이브·병영 길라잡이 | 노션 DB 1개 (`분류`로 구분) | `NOTION_DB_ARCHIVE` |
| 메인 배너 | 노션 DB | `NOTION_DB_BANNERS` |
| 건의 답변 | 노션 DB | `NOTION_DB_SUGGEST` |
| 메인 팝업(제휴·행사·공지) | 노션 DB | `NOTION_DB_POPUPS` |

| 페이백 현황(집계) | 구글 시트의 `요약` 탭 | `PAYBACK_CSV_URL` |
| 사이트 링크·학생회실 주소·이메일·인사말·서명·단체 사진 | 노션 DB (정해진 항목 이름, 3-9) | `NOTION_DB_SETTINGS` |
| 집행부 명단(매년 교체) | 노션 DB (3-11) | `NOTION_DB_COUNCIL` |
| 집행부 부서(이름·설명·순서) | 노션 DB (3-10) | `NOTION_DB_UNITS` |

- **학과 소개를 코드에 두는 이유**: 연 1회 미만으로 바뀌고, 웹 조사로 만든 내용이라 `(확인 필요)` 표기를 확인한 뒤 한 번에 고치는 편이 안전합니다. 자주 바뀌는 운영 정보(링크·주소·인사말·명단)만 노션으로 옮겼습니다.
- 환경변수를 **설정하지 않은 항목은 기본(예시) 데이터**가 보입니다. 항목별로 따로 켤 수 있습니다.
- 노션/구글에서 불러오다 실패해도 사이트는 죽지 않고 기본 데이터를 보여 줍니다.

## 2. 최초 1회 설정

### 2-1. 노션 연동
1. <https://www.notion.so/profile/integrations> 에서 **새 통합(Internal integration)** 을 만듭니다. 이름은 자유(예: `int-website`), 권한은 **콘텐츠 읽기**만 있으면 됩니다.
2. 만들어진 **Internal Integration Secret** 을 복사합니다 → 환경변수 `NOTION_TOKEN`.
3. 아래 3장의 표대로 DB(데이터베이스)를 만듭니다. 전체 페이지 데이터베이스를 쓰세요(인라인 DB는 id 찾기가 어렵습니다).
4. 각 DB 페이지 우측 위 `···` → **연결(Connections)** → 방금 만든 통합을 추가합니다. **DB마다 해야 합니다.** (빠뜨리면 사이트에 404/401 경고가 나고 기본 데이터가 보입니다.)
5. DB id 복사: DB 페이지 우측 위 **공유 → 링크 복사**. 주소가 `https://www.notion.so/내워크스페이스/abcdef1234567890abcdef1234567890?v=...` 형태라면, `?v=` 앞의 32자리 `abcdef1234567890abcdef1234567890` 이 DB id 입니다 → 해당 `NOTION_DB_*` 환경변수.

#### 자동으로 만들기 (선택): `npm run notion:setup`
**개발자(또는 터미널을 쓸 수 있는 사람)가 한 번 실행**하면 됩니다. 위 3~4단계(DB 12개 생성·속성 이름 맞추기)를 명령 한 번으로 대체합니다.
1. 통합 권한에 **콘텐츠 삽입(Insert content)** 을 추가합니다. (읽기만 있으면 DB를 만들 수 없습니다.)
2. DB를 모아 둘 **빈 부모 페이지**를 하나 만들고, 그 페이지 `···` → **연결(Connections)** 에서 통합을 추가합니다.
3. `.env.local` 에 `NOTION_TOKEN` 과 `NOTION_PARENT_PAGE_ID`(부모 페이지 id 또는 주소)를 넣습니다. `--parent <id|URL>` 로 직접 줘도 됩니다.
4. 먼저 `npm run notion:setup -- --dry-run` 으로 만들 내용을 확인합니다(토큰 없이도 동작, 노션 호출 없음).
5. `npm run notion:setup` 을 실행합니다. 끝나면 Vercel에 붙여 넣을 `NOTION_DB_*=값` 줄이 출력됩니다.
   - `--seed`: `src/content` 예시 데이터를 행으로 추가합니다(`공개` 체크). 이미 행이 있는 DB는 건드리지 않습니다.
   - `--write-env`: `.env.local` 의 `NOTION_DB_*` 키만 갱신합니다(다른 키는 그대로).
6. `npm run content:check` 로 점검합니다.

실행 후 노션에서 확인할 것:
- [ ] 부모 페이지 아래에 `인트 · …` DB 12개가 모두 보인다.
- [ ] 각 DB에 `공개` 열(체크박스)이 있다. (`--seed` 로 넣은 예시 행은 `공개`가 체크되어 있다.)
- [ ] 사이트에 보여 줄 행만 `공개`에 체크되어 있다.

중간에 실패하면(예: 토큰 오류) 그때까지 만든 DB id 가 출력됩니다. 원인을 고친 뒤 같은 명령을 다시 실행하면 이미 만든 DB는 재사용하고 나머지만 만듭니다.

같은 부모 페이지에서 다시 실행해도 `인트 · 공지사항` 처럼 같은 제목의 DB가 있으면 새로 만들지 않고 기존 DB id 를 씁니다. 이미지(배너)는 파일 업로드가 필요해 시드하지 않습니다.

### 2-2. 구글 시트 (페이백)
1. 시트에 **`요약` 탭**을 만들고 아래처럼 **A열=항목, B열=값** 으로 씁니다. (계산은 다른 탭에서 하고, 이 탭에는 합계 값만 넣으세요. **개인정보 금지**)

   | A | B |
   | --- | --- |
   | 총예산 | 500,000 |
   | 지급액 | 310,000 |
   | 지급인원 | 9 |
   | 신청기간 | 2026.10.13 ~ 11.07 |
   | 다음지급일 | 2026-11-14 |
   | 갱신일 | 2026-10-27 |

   숫자에는 쉼표·`원`이 있어도 됩니다. 날짜는 `2026-11-14` 또는 `2026.11.14` 형식. 항목 이름이 다르거나 값이 하나라도 틀리면 기본 데이터가 보입니다.

   소진율이 80%·95%를 넘으면 경고 표시(⚠ 예산이 얼마 남지 않았어요 / ⛔ 곧 마감돼요)와 막대 색 변화가 자동으로 나옵니다. 따로 설정할 것은 없어요.
2. **파일 → 공유 → 웹에 게시** → 범위를 **전체 문서가 아니라 `요약` 탭만** 선택 → 형식 **쉼표로 구분된 값(.csv)** → 게시.
3. 나온 URL을 복사 → `PAYBACK_CSV_URL`. (다른 탭은 게시하지 마세요. 게시된 탭은 인터넷에 공개됩니다.)

### 2-3. 구글 캘린더 (학사일정)
1. 학사일정 전용 캘린더를 만들고 일정을 입력합니다. 종일 일정이면 시작~종료일을 지정하세요.
2. 캘린더 **설정 및 공유** → **캘린더 통합** → **비공개 주소(iCal 형식)** 를 복사합니다. (캘린더를 공개했다면 **공개 주소(iCal 형식)** 도 됩니다. 비공개 주소는 비밀번호처럼 다루세요.)
3. 복사한 `.ics` 주소 → `ACADEMIC_ICS_URL`.
4. 한계: **반복 일정은 첫 번째 날짜만** 표시됩니다. 매주/매년 반복 대신 일정을 따로 입력하세요. 반복 일정 중 **특정 회차만 수정한 일정**(구글 캘린더에서 "이 일정만" 수정)은 표시되지 않으니, 수정한 회차를 보여 주려면 별도 일정으로 새로 입력하세요. 오늘 기준 앞뒤 1년 안의 일정만 표시됩니다.

### 2-4. Vercel 환경변수 입력
1. Vercel 프로젝트 → **Settings → Environment Variables**.
2. 아래 변수를 `Production`(필요하면 `Preview`)에 추가합니다. 이름은 `.env.example` 참고.
   `NOTION_TOKEN`, `NOTION_DB_NOTICES`, `NOTION_DB_CONTESTS`, `NOTION_DB_PARTNERS`, `NOTION_DB_FAQ`, `NOTION_DB_DOCS`, `NOTION_DB_BANNERS`, `NOTION_DB_POPUPS`, `NOTION_DB_SUGGEST`, `ACADEMIC_ICS_URL`, `PAYBACK_CSV_URL`, `REVALIDATE_SECRET`
3. 저장 후 **Deployments → 최신 배포 → Redeploy** 를 한 번 눌러야 새 환경변수가 적용됩니다.
4. 로컬 개발은 `.env.local` 에 같은 이름으로 넣습니다 (커밋 금지).

## 3. 노션 DB 속성표

공통: 모든 DB에 **`공개`(체크박스)** 가 있어야 하며, 체크된 행만 사이트에 나옵니다. 속성 이름·형식이 다르면 해당 행이 건너뛰어집니다. 줄바꿈은 `Shift + Enter` 로 합니다.

**중복 주의:** 공지의 `번호`, 공모전·제휴의 `슬러그`, 자료실의 `슬러그`(같은 분류 안)는 **겹치면 안 됩니다.** 겹침 처리는 5장 문제 해결을 참고하세요.

### 3-1. 공지사항 (`NOTION_DB_NOTICES`)

본문은 노션 페이지를 열어 그 안에 적습니다 (문단·제목·글머리/번호 목록·인용·콜아웃·구분선·체크리스트가 구조 그대로 표시됩니다).

| 속성 이름 | 형식 | 필수 | 예시 | 비고 |
| --- | --- | --- | --- | --- |
| 제목 | 제목(Title) | 필수 | 2026 학술제 참가팀 모집 |  |
| 번호 | 숫자 | 필수 | 6 | 겹치지 않는 양의 정수. 주소(/notice/6)에 쓰입니다 |
| 유형 | 선택 | 필수 | 행사 | 일반·행사·카드뉴스 중 하나 |
| 날짜 | 날짜 | 필수 | 2026-10-26 | 게시일 |
| 행사기간 | 날짜 | 선택 | 2026-11-03 → 2026-11-14 | 캘린더에도 표시할 때만. 하루면 시작일만 |
| 카드뉴스 | 파일 | 선택 | (이미지 여러 장 업로드) | 카드뉴스 이미지를 인스타그램 업로드 순서대로, 최대 20장. 없으면 일반 공지 |
| 인스타그램 | URL | 선택 | https://www.instagram.com/p/xxxx | 인스타그램 원본 게시물 링크(instagram.com 주소만 허용) |
| 공개 | 체크박스 | 필수 | 체크 | 체크된 행만 사이트에 나옵니다 |

#### 카드뉴스 올리기

인스타그램 카드뉴스와 같은 내용을 공지로 게시하는 방법입니다.

1. 공지 DB에 새 행을 만들고 `유형`을 **카드뉴스**로, `번호`·`제목`·`날짜`를 채웁니다.
2. `카드뉴스` 속성에 이미지를 **인스타그램에 올린 순서와 같은 순서**로 올립니다. 최대 20장, 권장 크기 1080×1350(4:5).
3. 원본 게시물 링크가 있으면 `인스타그램`에 붙여 넣습니다(`https://www.instagram.com/…` 주소만 표시됩니다).
4. **페이지 본문에 이미지 속 글을 요약해서 적어 주세요.** 이미지 안의 글자는 검색·스크린리더가 읽을 수 없습니다.
5. `공개`를 체크합니다. 공지 상세에서는 본문 위에 넘겨 보는 슬라이더(스와이프·이전/다음·←/→·"2 / 6")가 나오고, 목록에는 "카드뉴스" 배지와 장수가 표시되며, 공유할 때 첫 장이 썸네일로 쓰입니다. 공지 목록 상단 "카드뉴스" 탭으로 모아 볼 수 있습니다.
6. 기존 DB에는 속성이 자동으로 추가되지 않으니, 노션에서 `카드뉴스`(파일)·`인스타그램`(URL) 속성을 직접 추가하고 `유형`에 **카드뉴스** 옵션을 만드세요. 이름이 다르면 반영되지 않습니다(`npm run content:check`로 점검).

#### 취업·병영 글 올리기

1. 아카이브 DB에 새 행을 만들고 `제목`·`슬러그`·`분류`·`날짜`를 채웁니다. 목록에 보일 `주제`와 `요약`도 적어 주세요.
2. 페이지를 열어 본문을 적습니다. 문단·제목(1~3)·글머리/번호 목록·인용·콜아웃·구분선·체크리스트가 구조 그대로 표시됩니다. 이미지는 **외부 주소(https)로 넣은 이미지**만 보입니다. 업로드한 이미지는 `첨부` 속성에 올려 주세요.
3. PDF·이미지 파일은 `첨부`에 올립니다(여러 개 가능). 외부 원문이 있으면 `링크`에 붙여 넣습니다.
4. 목록 위쪽에 계속 두려면 `고정`을 체크합니다. 고정 글이 맨 위에, 그다음 날짜 최신순입니다.
5. `공개`를 체크하면 `분류`에 따라 취업 아카이브(`/archive/career`) 또는 병영 길라잡이(`/archive/military`)에 나타납니다. 내릴 때는 `공개`를 해제하거나 행을 삭제합니다.
6. 병영 길라잡이 목록 맨 위의 "병역 길라잡이" 카드는 사이트 설정 "병역 길라잡이"(`notionMilitaryGuide`, `src/content/site.ts`)를, 취업 아카이브 목록 맨 위의 "인융 인터뷰 아카이브" 카드는 사이트 설정 "인융 인터뷰 아카이브"(`notionInterview`)를 씁니다. 옛 이름("군입대 백서"·"공모전 정보")으로 만든 행도 계속 인식되며, `npm run content:check` 가 새 이름으로 바꾸라고 ⚠️ 로 "노션 '사이트 설정'의 '군입대 백서' 행 이름을 '병역 길라잡이'(으)로 바꿔 주세요" 처럼 행 이름을 그대로 넣어 알려 줍니다. 카드 제목에는 "(노션)"을 붙이지 않고, 외부 링크임은 ↗ 아이콘·"노션 바로가기" 작은 글씨와 스크린리더용 "(새 창)"으로 알립니다.
7. `주제` 옵션은 노션에서 새로 추가해도 목록 탭에 자동으로 생깁니다(코드 수정 불필요).
8. `고정`은 2~3개 이하로 쓰기를 권장합니다. 많아지면 최신 글이 아래로 밀립니다.
9. 첨부 파일은 PDF를 권장하며, 글당 최대 20개까지 표시됩니다.
10. 개인정보·실제 부대 정보 등 민감한 내용은 올리지 않습니다. 기존 노션 환경에서는 `npm run notion:setup`이 없는 DB(아카이브)만 새로 만듭니다.

#### 팝업 올리기·내리기
1. 팝업 DB에 새 행을 추가하고 `제목`·`슬러그`·`분류`·`기간`을 채운 뒤 `공개`를 체크합니다. 최대 약 10분 뒤(또는 4장의 즉시 갱신) 메인에 뜹니다.
2. **기간**은 시작일 → 종료일을 모두 넣습니다. 한국 시간 기준으로 종료일 당일까지 보입니다. 하루짜리는 시작일만 넣어도 됩니다.
3. **이미지**는 가로 4:3 정도의 포스터 1장을 노션에 직접 올립니다(자동으로 만료되지 않는 사이트 내부 경로 사용). 없으면 분류가 적힌 자리 표시가 나옵니다.
4. **링크**는 `/partners/oo-restaurant` 같은 사이트 안 경로 또는 `https://…` 주소입니다. 비우면 "자세히 보기" 버튼이 나오지 않습니다.
5. 내리기: `공개`를 해제하거나 행을 삭제합니다. 기간이 지나면 저절로 사라집니다.

예시:

| 제목 | 슬러그 | 분류 | 기간 | 내용 | 링크 | 버튼문구 | 순서 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| OO식당 제휴 오픈 | p-partner-open | 제휴 | 2026-10-28 → 2026-11-14 | 학생증을 보여주면 전 메뉴 10% 할인! | /partners/p1 | 제휴 보러가기 | 1 |
| 오픈랩 탐방 신청 | p-event-lab | 행사 | 2026-10-30 → 2026-11-10 | 연구실을 직접 둘러보는 오픈랩 탐방 | /notice | 공지 확인하기 | 2 |

- 공모전은 기존대로 공모전 DB의 `팝업` 체크로 띄우며, 같은 팝업창에 합쳐집니다(분류 "공모전", 순서는 맨 뒤). 같은 슬러그가 팝업 DB에도 있으면 팝업 DB 행이 우선입니다.
- 팝업이 여러 개면 한 팝업창에서 이전/다음(점, "1 / 3", 키보드 ←/→)으로 넘겨 봅니다.
- 방문자가 "오늘 하루/일주일간 보지 않기"를 고르면 **그때 열린 팝업 전체**가 숨겨집니다. 나중에 새 팝업을 올리면 그 팝업만 다시 뜹니다.
- 기존 DB 구성이 끝난 상태라면 `npm run notion:setup` 이 팝업 DB만 새로 만듭니다(같은 부모 페이지에서 재실행, 이미 있는 DB는 재사용).

| 공개 | 체크박스 | 필수 | 체크 | 체크된 행만 사이트에 나옵니다 |

### 3-11. 집행부 (`NOTION_DB_COUNCIL`)

| 속성 이름 | 형식 | 필수 | 예시 | 비고 |
| --- | --- | --- | --- | --- |
| 이름 | 제목(Title) | 필수 | 홍길동 |  |
| 학과 | 텍스트 | 선택 | 컴공 | 학과·전공 약칭 |
| 부서 | 선택(Select) | 필수 | 홍보부 | 부서 DB의 이름과 같게 |
| 직책 | 텍스트 | 선택 | 회장 | 일반 부원은 비움 |
| 부장 | 체크박스 | 선택 | 체크 | 부서마다 한 명 |
| 순서 | 숫자 | 선택 | 1 | 작은 수가 먼저. 비우면 맨 뒤 |
| 공개 | 체크박스 | 필수 | 체크 | 체크된 행만 사이트에 나옵니다 |

규칙:
- `부서`가 부서 DB에 없는 사람(오타 포함)은 **"기타" 그룹**으로 보이고 경고가 남습니다.
- 부장이 한 부서에 여러 명이면 순서가 앞선 **첫 번째만** 부장으로 표시합니다. 부장은 부서 안에서 맨 앞에 나옵니다.
- 총원은 명단 행 수에서 자동으로 계산합니다.
- 집행부 DB만 연결하고 부서 DB를 연결하지 않으면 기본(예시) 부서 이름·설명으로 묶습니다.
- 학과 약어에 마우스를 올리면 정식 명칭이 보이는 기능은 코드의 약어 표(`majorNames`)를 씁니다. 표에 없는 약어는 글자만 보입니다.
- `npm run notion:setup -- --seed` 는 현재 25명·6개 부서를 그대로 넣습니다. 다음 집행부는 행만 바꾸면 됩니다.

## 4. 반영 시간과 즉시 갱신

- 노션·구글에서 고친 내용은 **최대 약 10분 안에** 사이트에 반영됩니다.
- 바로 반영하고 싶으면 아래 명령으로 캐시를 비웁니다. 다음 방문부터 새 내용이 보입니다. (`REVALIDATE_SECRET` 과 같은 값을 헤더에 넣습니다.)

```bash
curl -X POST https://<사이트주소>/api/revalidate \
  -H "x-revalidate-secret: <REVALIDATE_SECRET 값>"
# 성공: {"ok":true,"revalidatedAt":"..."}  / 비밀값 불일치: 401 / 서버에 비밀값 미설정: 500
```

- 노션에 올린 이미지(배너 등) 주소는 약 1시간 뒤 만료되므로, 사이트는 10분마다 새 주소를 받아옵니다.
- 이미지는 노션에 직접 올려도 됩니다(자동으로 만료되지 않는 사이트 내부 경로를 사용).

## 4-1. 방문 통계 보기

Vercel Web Analytics·Speed Insights를 씁니다. **쿠키를 쓰지 않고 개인 식별 정보를 모으지 않습니다.** 통계 스크립트는 Vercel **운영(Production) 배포**에서만 들어가므로, 로컬·CI·PR 미리보기에서는 아무것도 전송되지 않아요.

**집계 범위**: 운영 배포에서만 집계되며, 미리보기·로컬 방문은 집계되지 않습니다.

**처음 한 번 켜기** (저장소 관리자)
1. Vercel 프로젝트 → **Analytics** 탭 → **Enable**
2. Vercel 프로젝트 → **Speed Insights** 탭 → **Enable**
3. 켠 뒤 다시 배포하면 이후 방문부터 집계됩니다. (켜기 전 방문은 집계되지 않아요.)

**보는 법**
- **Analytics** 탭: 오른쪽 위에서 기간(24시간·7일·30일 등)을 고르고, **Pages**에서 상위 페이지(어떤 메뉴를 많이 보는지), Referrers·Devices 등을 봅니다.
- **Speed Insights** 탭: 실제 방문자 기준 LCP 등 성능 점수를 봅니다. 데이터가 쌓이는 데 하루쯤 걸려요.

**커스텀 이벤트**: 공모전 팝업 "자세히 보기"(`popup_detail`), 페이백 "신청하기"(`payback_apply`), 카카오톡 FAB(`kakao_fab`) 클릭을 기록합니다. 이벤트 이름은 `src/lib/analytics.ts`의 `EVENTS`에 있어요. 커스텀 이벤트는 Vercel 유료 플랜 기능일 수 있어, 무료 플랜에서는 페이지뷰만 보일 수 있습니다. (확인 필요)

## 5. 문제 해결

먼저 **설정 점검 명령**을 실행해 보세요. (`.env.local` 에 환경변수를 넣고, 저장소 폴더에서 실행)

```bash
npm run content:check
```

노션 DB별로 속성 이름·형식이 맞는지, `공개` 체크된 행이 몇 개이고 그중 몇 개가 유효한지, 학사일정·페이백 주소가 읽히는지를 ✅/⚠️/❌ 로 알려 줍니다. 설정하지 않은 항목은 "설정 안 됨"으로 표시됩니다. ❌ 가 있으면 종료 코드 1.


| 증상 | 확인할 것 |
| --- | --- |
| 행이 사이트에 안 보임 | 1) `공개` 체크 2) 필수 속성이 모두 채워졌는지 3) 슬러그가 영문 소문자·숫자·하이픈(`a-z0-9-`)뿐인지 4) 공지는 `번호`가 있는지, `유형`이 `일반`/`행사` 중 하나인지 5) 자료실은 `분류` 값이 표와 같은지 |
| 로그에 `Notion 400 ... Could not find property with name or id: 공개` | 그 DB에 `공개` 체크박스 속성이 없거나 이름이 다릅니다. 3장 표의 이름·형식으로 추가하세요. (`순서`·`날짜` 등 정렬에 쓰는 속성이 없을 때도 같은 형태의 400이 납니다) |
| 링크 버튼이 비활성/자리표시로 보임 | 링크는 `https://`·`http://` 또는 사이트 내부 `/경로`만 허용됩니다. 이미지는 `https://` 만 허용됩니다. |
| 한 DB 전체가 기본(예시) 데이터로 보임 | DB에 통합을 연결했는지(2-1의 4), DB id·`NOTION_TOKEN` 값, Vercel 재배포 여부. Vercel **Logs** 에서 `[data] ... 실패, 목 데이터 사용` 경고를 찾으세요. |
| 슬러그·번호가 겹침 | 슬러그(또는 공지 번호)가 겹치면 **먼저 만든 행**이 사이트에 나오고, 나머지는 무시됩니다. (Vercel Logs 에 `중복 건너뜀` 경고) |
| 행 하나만 빠짐 | Vercel Logs 의 `[data] NOTION_DB_... 행 건너뜀 (...): 이유` 메시지에 이유가 나옵니다. |
| 속성 이름을 바꿨더니 사라짐 | 코드의 이름과 달라서입니다. 3장 표의 이름으로 되돌리세요. |
| 학사일정이 안 보임 | `.ics` 주소인지, 일정이 오늘 기준 ±1년 안인지, 반복 일정이 아닌지 확인 |
| 페이백 숫자가 예시 그대로 | `요약` 탭 항목 이름·값 형식(2-2)과 게시 형식이 CSV인지 확인 |
| 고쳤는데 그대로 | 최대 10분 대기 또는 4장의 `curl` 로 즉시 갱신 |

## 6. 새 집행부 인수인계 체크리스트

코드를 고칠 필요 없이 노션에서 모두 끝납니다.

- [ ] **노션 권한**: 새 담당자를 워크스페이스에 초대하고, `인트 · …` DB가 모여 있는 부모 페이지의 편집 권한을 줍니다. 통합(Integration)을 새로 만들었다면 DB마다 **연결(Connections)** 을 다시 추가하고 Vercel의 `NOTION_TOKEN` 을 바꿉니다.
- [ ] **집행부 DB 교체** (`NOTION_DB_COUNCIL`): 지난 집행부 행을 지우거나 `공개` 체크를 끄고, 새 집행부를 한 줄씩 추가합니다(`이름`·`학과`·`부서`·`직책`·`부장`·`순서`). 부서가 달라지면 **부서 DB**(`NOTION_DB_UNITS`)도 함께 고칩니다. `부서` 선택값은 부서 DB의 `이름`과 같아야 합니다. 총원은 자동으로 계산됩니다.
- [ ] **인사말·서명** (사이트 설정 DB): `인사말`·`인사말 서명` 행을 새 회장 내용으로 고칩니다.
- [ ] **단체 사진** (사이트 설정 DB): `단체 사진` 행의 `파일`에 새 사진을 올립니다.
- [ ] **링크 확인** (사이트 설정 DB): 카카오톡 채널, 인스타그램 주소·아이디, 이메일, 학생회실 주소, 건의함·페이백 폼, 병역 길라잡이, 인융 인터뷰 아카이브, 구글 캘린더 구독 링크가 지금도 유효한지 하나씩 눌러 봅니다.
- [ ] 구글 캘린더·시트, Vercel, GitHub 관리자 권한과 `REVALIDATE_SECRET` 교체는 README의 인수인계 항목을 따릅니다.
- [ ] 마지막으로 `npm run content:check` 또는 사이트를 열어 학생회 소개·푸터가 바뀌었는지 확인합니다(최대 10분, 바로 보려면 4장의 강제 새로고침).
